# The tied LM head as NN vs NT, and an NT tile sweep for it — M5 Pro, 2026-09-30
#
# Question: can the bf16 forward drop its packed [hidden, vocab] head and run
# the head as an NT product over the [vocab, hidden] embedding table (what
# the f32 model now does), without losing speed? Shape: 1024 rows,
# N = 248320, K = 2048. `TESSL_GEMM_TUNE=1 cargo build --release --bins`,
# then `target/release/bench_gemm_tnnt_tune`; two full runs, the second
# with round-two variants (taller row tiles) added. The NT dx rows below
# show what each tile does to the training shapes the production NT kernel
# (128x64 sg4) serves.
#
# Finding: the best NT tile (256x64 sg8: each row tile streams the 1 GB
# table once, so 4 row tiles read it 4 times against 128x64's 8) reaches
# 35.9 / 37.1 ms against the NN head's 34.2 / 33.4 ms: 5-11% slower. Taller
# tiles do not help (512x64 sg16 38.2, 1024x32 sg16 39.4; 512x64 sg8 122).
# 256x64 sg8 would also halve the NT dx_mlp_in shape (0.51x), so it could
# only be a head-specific kernel. Decision: the bf16 model keeps its packed
# NN head (see docs/qwen35.md, "From torch").
