#  1. It finds the metallib by scanning bench_gemm_sweep for the path
#     string build.rs bakes in. The runtime embeds the bytes

#     string is not in the binary: "cannot resolve the benchmark's embedded
#     metallib ... found []". `--metallib PATH` works around it (the bytes
#     of target/release/build/tessl-*/out/default-*.metallib were found
#     inside the binary, so that file is the one it runs).
#  2. With the metallib given, the source scan misses 29 entry points the
#     metallib exports, all qwen35 kernels stamped by macros it does not
#     parse (qwen35_adamw_*_g*_m*, qwen35_attn_tiled_lse_h256_q32_k32_sg4,
#     qwen35_{head,token}_rows_to_bank_*, qwen35_window_copy_*), so it
#     refuses ("The scan is wrong; fix it"). No file under kernels/qwen35*
#     changed on this branch. Every GEMM entry point is matched.
#  3. Two suites never print the KERNEL_TRACE line the sweep reads:
#     bench_gemm_sweep and bench_nn_kernels have no emit_kernel_trace
#     (neither file changed on this branch). bench_nn_kernels also exits 1
#     under the BENCH_WARMUP=0 the sweep passes: sample_loop starts `token`
#     at 0 and only a warmup call sets it, so the first timed token reads
#     as "token changed from 0 to 117223"; it passes at BENCH_WARMUP=1.
#
