# Fused gate/up/SwiGLU GEMM (gemm_swiglu_bf16) against two GEMMs + swiglu — M5 Pro, 2026-10-10
#
# The prototype lives in the commit that adds this file and is removed in
# the next. matmul2d_tensorops_bf16_swiglu (128x64 sg4) and its 64x64 twin
# run gate's and up's products over the same A tile into two register
# accumulators and store bf16(silu(g) * u); bit for bit the production two
# GEMMs + qwen35::swiglu on every tested shape and tile
# (fused_swiglu_gemm_is_the_two_gemms_then_swiglu), so the logits do not move.
#
# Acceptance bar, fixed before the forward was timed (from the decision
# recorded in docs/qwen35.md): the 24-layer forward faster by >= 3% in every
# statistic at T = 1024 and 2048, with no regression at T = 512 or decode.
#
# Finding: declined. The fused kernel is slower everywhere it was timed.
# Kernel units (in-process ABBA, 15 rounds, ratio fused / unfused): the
# activation 1.03x at T = 1 and 1.075-1.087x at T = 512-2048; the MLP block
# 1.02x at T = 1 and 1.054-1.058x at T = 512-2048. Two variants were tried
# and lost the same way or worse: interior tiles on offset pointer tensors
# (as the plain kernel does; 1.084-1.089x), and the 64x64 tile at large M
# (1.27-1.36x at T = 512 and 1024, 0.98x at 2048; same bits as 128x64).
# Whole forward (Qwen35Model random 2B tower, --model-forward, two frozen
# builds, bench/paired_bins.sh, 5 rounds interleaved, min of each process's
# median): T = 1024 143.19 -> 148.47 ms (1.037x), T = 2048 277.07 -> 286.46
# ms (1.034x). The two accumulators per thread are the likely cost (twice the
# plain kernel's registers at 128x64); the saved f32 write, read and dispatch
# do not cover it.
#
# Conditions: shared machine; other agent sessions' GPU work (ioreg 84-92%
# busy before the runs), 1-minute load ~8-23. Ratios are the headline.
#
