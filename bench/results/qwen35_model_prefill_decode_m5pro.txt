bench_qwen35_layers on Qwen35Model: 8K prefill, decode baseline, before/after (M5 Pro, 2026-10-14)

Built from tessl commit cf537a1 (branch bl/qwen35bench, from 0055612), release,
binary `bench_qwen35_layers`. "Old" below is the 0055612 binary (the bench's own
layer wiring), run with --gdn-scan16 so both use the library-default Cols16 scan.
Every GPU run is under Lappi's mac_heavy lock. Weights: "random" is
Qwen35Model::random(qwen35_2b, Bf16, seed 0x51); "REAL" is the instruct
Qwen3.5-2B checkpoint, models--Qwen--Qwen3.5-2B/snapshots/15852e8c..., loaded
at bf16 with the packed head. Power: AC, powermode 2 (pmset), recorded per run.

CAVEAT, GPU not strictly idle: the lock serialises Lappi's jobs only. The
GPU utilisation printed before each run (ioreg "Device Utilization %") is 0 at
the start of the first section and in round 1 of the 8K comparison, but other
sessions' GPU work shows up in rounds 2-3 and the decode runs (up to ~60-99%
on the first sample, which can also be this binary's own predecessor exiting).
Read the minima, and round 1 as the clean pair.

== RULING: 3,797 vs 6,213 tok/s (GAP-QDM-8K-PREFILL-3797-VS-REPORTED-6213-TOKS-2026-10-03)
On this tree, 8K prefill on Qwen35Model with the REAL Qwen3.5-2B weights, min of 9:
  tower (begin + 24 layers + final norm):  1252.3 ms = 6541 tok/s  (round 1, GPU idle at start)
  forward_rows(Last) (tower + LM head):    1307.0 ms = 6268 tok/s  (best of all runs; round 1: 1318.5 ms = 6213 tok/s)
  prefill (head + decode state):           1298.4 ms = 6309 tok/s  (best; round 1: 1319.5 ms = 6208 tok/s)
The lowest figure in any run is 5,775-5,900 tok/s, under visible GPU contention.
None is near 3.8-4.1k. By Fable's rule (~6.2k on today's tree = the qd-metal
prefill path is the gap; ~3.8-4.1k = a tessl regression) the gap is qd-metal's,
not a tessl regression. The old bench's own figure on this tree (random
weights, 0055612) is 6012 / 5684 / 5713 tok/s (its "forward" column), the same
band as the 6,213 reported on 2026-09-28. Random and real weights time the
same in round 1 (1252.5 vs 1252.3 ms tower).

== DECODE BASELINE (--decode=4096, async encode, tok/s from min of 32 steps)
Decode::step per token, measured with infer_trace over 4 separate traced steps:
  host waits (synchronize) per token ......... 1
  command buffer commits per token ........... 1
  cold allocations per token ................. 3
  dispatches per token ....................... 273
The 3 cold allocations are Decode::step's two 4-byte buffers (suffix_len,
q_pos: alloc_buffer_from_u32) plus the one-token id buffer Qwen35Model::embed_ids
makes (alloc_buffer_from_u32 again). The brief expected 2; the third is the
embedding gather's. A GPU-resident decode loop removes all three and the wait.
  random weights: decode 17.302 ms/token min (57.8 tok/s), median 18.143 ms (55.1);
                  prefill P=4096 min 575.6 ms (7116 tok/s)
  REAL weights:   decode 19.894 ms/token min (50.3 tok/s), median 21.435 ms (46.7);
                  prefill P=4096 min 690.1 ms (5935 tok/s)  [GPU contended: an
                  earlier run had it at 570.0 ms / 7186 tok/s and decode
                  17.715 ms / 56.4 tok/s, see the first log below]
Each step includes the head and the 1 MB logits read. The sampler is not timed.
The token ids are a fixed pattern, not sampled.
