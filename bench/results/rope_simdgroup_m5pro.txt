rms_qkv_rope one-simdgroup-per-row A/B — M5 Pro, 2026-09-04
===========================================================

Kernel: `rms_qkv_rope` (PosConst; the posbuf and kv_store variants share the
row routine). Previous: one thread per (token, head) row, three serial
passes. New: one 32-lane simdgroup per row, lane l owns the pair
(p, p + D/2) for p ≡ l (mod 32), `simd_sum` for the sum of squares.

Method: paired, order-balanced, in-process A/B with the previous kernel kept
under a temporary name. Twenty dispatches per command buffer (async encode,
auto barriers), ten calls per arm per round (per-call median), six rounds
alternating arm order, median of rounds. rotary_dim = D, theta 1e4.

ratio = previous time / new time (> 1: the simdgroup kernel is faster)

Reading: decode and small-T shapes are latency bound on the old kernel (a
single thread walking 256 elements three times); the simdgroup kernel is
3.4-11.5x faster there and 1.3-1.7x at long prefill, where the old grid
already had thousands of threads but uncoalesced rows. Numerics: the
reduction reassociates (low bits); tests/qkv_rope.rs compares against an f64
reference and pins that a row is bit-identical wherever it sits in the grid.
